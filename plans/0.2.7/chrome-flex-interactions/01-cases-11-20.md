## Overview

Convert manifest cases 11 through 20 into reviewed interaction fixtures. Keep
each case tied to its Chromium source path, then choose the smallest Go
evidence seam that can prove the named behavior. The fixture, focused-test, and
reference-capture slice is now present for all ten cases. The ten manifest
entries have completed status; strict geometry tests own the behavior claims.

This batch contains six direct layout candidates and four cases that need a
Chrome reference or a larger engine investigation. Do not mark a case complete
because its HTML renders to a readable PDF. The focused behavior assertion is
the completion gate.

## Executive summary

Work in this order:

1. Lock the ten manifest entries and their source paths.
2. Port the direct layout cases that reuse existing wrapping, alignment, and
   margin code.
3. Port the direction, baseline, percentage-basis, and minimum-size cases with
   explicit reference or unsupported-feature decisions.
4. Run the batch gates and update only the statuses supported by evidence.

The high-risk cases were baseline alignment, percentage flex basis in an
indefinite column, RTL column wrap-reverse, and automatic minimum size with
`overflow: clip`. They now have strict Go assertions. The reusable
`scripts/chrome_rects.py` probe records Chromium rectangles for the cases that
need a browser reference, while Go tests remain the completion gate.

## Definition of done

This ledger is complete when every case has a reviewed static fixture, a named
assertion at the target seam, a recorded validation result, and a manifest
status that matches the evidence. A generated PDF alone does not close a case.
