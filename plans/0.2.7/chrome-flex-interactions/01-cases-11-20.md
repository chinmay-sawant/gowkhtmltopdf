## Overview

Convert manifest cases 11 through 20 from scaffolds into reviewed interaction
fixtures. Keep each case tied to its Chromium source path, then choose the
smallest Go evidence seam that can prove the named behavior.

This batch contains six direct layout candidates and four cases that need a
Chrome reference or a larger engine investigation. Do not mark a case complete
because its HTML renders to a readable PDF. The focused behavior assertion is
the completion gate.

## Executive summary

Work in this order:

1. Lock the ten manifest entries and their source paths.
2. Port the direct layout cases that reuse existing wrapping, alignment, and
   margin code.
3. Port the direction, baseline, percentage-basis, and minimum-size cases with
   explicit reference or unsupported-feature decisions.
4. Run the batch gates and update only the statuses supported by evidence.

The likely high-risk cases are baseline alignment, percentage flex basis in an
indefinite column, RTL column wrap-reverse, and automatic minimum size with
`overflow: clip`. If the engine does not support a required behavior, record a
`blocked` or `unsupported` result with the exact source and next seam. Do not
weaken the assertion to obtain a pass.

## Existing evidence audit

The current Go tests are leads, not closure evidence for this ledger. The
manifest still marks all ten cases as `scaffold`, and several tests cover only
an adapted subcase or contain strict skips:

| Cases | Current evidence | What remains before closure |
| --- | --- | --- |
| 11 | Adapted wrap-reverse subcases pass. | Port the broader source matrix and prove line cross sizes, direction, and writing-mode branches. |
| 12 | The column-align-content test skips because column wrapping is absent. | Implement or explicitly defer column line formation and `align-content`. |
| 13 | Five auto-margin branches pass and five branches skip. | Add the reference coverage for logical margins, direction, writing mode, and reverse flow. |
| 14 | Horizontal baseline branches pass; vertical-writing branches skip. | Add real text baseline evidence or record the unsupported axis. |
| 15 | Per-line alignment passes; baseline remains incomplete. | Replace the generic fixture with source-faithful `align-self` combinations. |
| 16 | Normal stretch and explicit-size branches pass; margin-sensitive stretch skips. | Port the source margin case and prove that stretch preserves margins. |
| 17 | The percentage-basis test skips because stretch makes the nested column definite. | Preserve the indefinite main-size condition and fix cyclic percentage-basis resolution. |
| 18 | The RTL column wrap-reverse test skips because column wrapping is absent. | Add column line formation, wrap-reverse, and RTL cross-axis ordering. |
| 19 | An adapted row auto-margin test passes. | Replace the scaffold with a reviewed WPT adaptation and prove both main and cross-axis margins. |
| 20 | The automatic minimum with `overflow: clip` test skips. | Preserve nested min-content content and fix or explicitly defer the overflow-clip minimum. |

Do not promote an adapted passing subcase to `completed` until its fixture
matches the intended source behavior closely enough for the manifest claim.

## Phase 1.1: Port the wrapping and alignment cases

### Case 11: `legacy-multiline`

- [ ] Replace the scaffold in `test/Chrome/cases/legacy-multiline.html` with a
  static case that has at least two lines, a cross-size difference, and one
  direction or wrap-reverse branch from the Chromium source.
- [ ] Add a named geometry test under `internal/layout` that checks line
  assignment, item order, line cross sizes, and the final container height.
- [ ] Run the focused case test and the existing flex-flow regression tests.

### Case 12: `legacy-multiline-align-content-column`

- [ ] Preserve the wrapped-column setup from
  `third_party/blink/web_tests/css3/flexbox/multiline-align-content-horizontal-column.html`
  in the static fixture.
- [ ] Assert at least two `align-content` modes with line offsets measured
  relative to the flex container, not document coordinates.
- [ ] Run the case-12 test together with the case-11 wrapping test.

### Case 15: `legacy-multiline-align-self`

- [ ] Port the multi-line input from
  `third_party/blink/web_tests/css3/flexbox/multiline-align-self.html` and keep
  the item-level `align-self` declarations visible in the fixture.
- [ ] Assert that `start`, `center`, `end`, and stretch decisions use each
  line's cross size without moving an item into another line.
- [ ] Run the focused test with cases 11 and 12 before changing its manifest
  status.

### Case 16: `wpt-align-items-stretch`

- [ ] Port the margin and explicit-size branches from
  `third_party/blink/web_tests/external/wpt/css/css-flexbox/flexbox_align-items-stretch-2.html`.
- [ ] Assert the stretched border box, content box, and margin edges so a
  margin is not silently erased by stretch.
- [ ] Run the focused test and the existing alignment and border-box tests.

## Phase 1.2: Port direction, margins, and sizing interactions

### Case 13: `legacy-flex-flow-auto-margins`

- [ ] Capture the Chromium reference rectangles for the direction, writing
  mode, and column-reverse branches in the source fixture.
- [ ] Add a Go comparison that checks logical auto-margin placement and records
  any unsupported branch separately from a geometry failure.
- [ ] Run the reference probe and the Go focused test before changing status.

### Case 14: `legacy-flex-align-baseline`

- [ ] Determine whether baseline geometry is observable through Go box positions,
  text paint positions, or only a Chromium raster reference.
- [ ] Port the smallest static fixture that has different font sizes or margins
  and proves the baseline relationship.
- [ ] Mark the case `completed` only after the baseline assertion passes; use
  `blocked` or `unsupported` with a reason if the engine lacks the required
  baseline path.

### Case 17: `wpt-flex-basis-011`

- [ ] Port the indefinite nested-column percentage-basis input from
  `third_party/blink/web_tests/external/wpt/css/css-flexbox/flex-basis-011.html`.
- [ ] Assert that the percentage basis falls back to content sizing when the
  main-axis containing block is indefinite.
- [ ] Add a regression for the opposite definite-containing-block branch if
  the same code path can distinguish the two cases.

### Case 18: `wpt-rtl-flow-reverse`

- [ ] Capture the logical and physical item order for the RTL,
  column-wrap-reverse case from the WPT source.
- [ ] Assert both column order and within-column item order against Chromium;
  do not validate only the final container bounds.
- [ ] Run the reference and Go checks with the existing RTL and vertical-axis
  tests.

### Case 19: `wpt-flexbox-margin-auto`

- [ ] Port the row auto-margin input from
  `third_party/blink/web_tests/external/wpt/css/css-flexbox/flexbox_margin-auto.html`.
- [ ] Assert positive free-space distribution, fixed item sizes, and cross-axis
  centering for every named item.
- [ ] Reuse the existing margin helpers where the invariant matches; add a new
  helper only if the case exposes a distinct layout decision.

### Case 20: `wpt-min-size-auto-overflow-clip`

- [ ] Port the narrow-container and overflow-clip branches from the WPT source.
- [ ] Assert the automatic minimum width and the overflow boundary separately.
- [ ] If `overflow: clip` is outside the supported subset, record the exact
  unsupported branch and keep the strict assertion visible.

## Definition of done

This ledger is complete when every case has a reviewed static fixture, a named
assertion at the target seam, a recorded validation result, and a manifest
status that matches the evidence. A generated PDF alone does not close a case.

## Out of scope

- Porting cases 21 through 40.
- Building Chromium or copying Blink's C++ test harness into Go.
- Marking a browser-reference case complete from a PDF page-count check alone.
