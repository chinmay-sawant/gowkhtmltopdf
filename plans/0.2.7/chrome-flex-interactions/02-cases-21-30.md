## Overview

Convert cases 21 through 30 from scaffolds into reviewed tests. This batch
connects wrapping and gaps to intrinsic sizing, writing modes, definite
percentages, absolute positioning, print fragmentation, and column auto
margins.

The batch mixes direct layout tests, browser-reference tests, and one golden
print fixture. Assign the evidence seam before implementing each case. Do not
force a browser-only assertion into a direct Go test, and do not use a readable
PDF as proof of geometry.

## Executive summary

Work from shared layout decisions toward cases that depend on them:

1. Convert row wrapping and gap placement.
2. Convert aspect-ratio, writing-mode, and automatic-margin interactions.
3. Convert definite percentage and absolute-positioning cases after confirming
   containing-block behavior.
4. Convert the print-fragmentation case as a golden fixture.
5. Run the batch gates and record every unsupported branch explicitly.

The highest-risk cases are nested aspect-ratio feedback, vertical writing
mode matrices, percentage absolute children, automatic minimum width from an
aspect ratio, and print fragmentation. Keep those cases small enough that a
failure identifies one layout decision.

## Existing evidence audit

Several cases already have passing Go adaptations, but the manifest still
marks all ten cases as `scaffold`. The fixture must match the source-backed
behavior before a passing adaptation can close a case.

| Cases | Current evidence | What remains before closure |
| --- | --- | --- |
| 21 | Row-wrap geometry passes in an adapted test. | Port the source's item count and margin pattern, then keep line assignment assertions. |
| 22 | Flexible column-gap geometry passes in an adapted test. | Port the source's flexible children and prove both edge and inter-item gaps. |
| 23 | Nested aspect-ratio cross-size feedback is explicitly blocked. | Preserve the nested source structure and fix the feedback path or record the engine boundary. |
| 24 | Horizontal writing branches pass; the vertical RTL matrix skips. | Split supported and blocked branches and capture the full logical-axis reference. |
| 25 | Percentage absolute-child adaptation passes. | Use an in-flow marker child like the source and prove the actual containing block. |
| 26 | Definite size from `min-height` passes in a Go adaptation. | Port the source's percentage child and update the fixture before changing status. |
| 27 | Percentage-height column-item adaptation passes. | Port the source red-parent and green-child setup and assert parent and child heights. |
| 28 | Aspect-ratio minimum-width adaptation passes. | Use the source-faithful replaced element and capture browser parity. |
| 29 | No dedicated golden test exists. | Add page-count, ordered-text, and fragmented-content evidence. |
| 30 | Column auto-margin geometry passes in a focused test. | Add the source's `flex-direction: column` and `align-self: center` branches to the fixture. |

Passing Go adaptations are useful starting points. They are not proof that the
current scaffold represents the Chromium case.

## Phase 2.1: Port wrapping and gaps

### Case 21: `wpt-flow-row-wrap`

- [ ] Replace the scaffold in `test/Chrome/cases/wpt-flow-row-wrap.html` with
  fixed item widths, margins, and a container that produces two known rows.
- [ ] Assert line membership, item order, line cross sizes, and container
  height in a focused `internal/layout` test.
- [ ] Run the case test with the existing row-wrap and multiline regressions.

### Case 22: `wpt-gap-002-ltr`

- [ ] Preserve the LTR column-gap branches from the WPT source in the static
  fixture.
- [ ] Assert the first item edge, every inter-item gap, and the last item edge;
  do not validate only the total container size.
- [ ] Run the focused test with the existing gap tests and verify that no
  generated PDF is used as the geometry oracle.

## Phase 2.2: Port intrinsic, logical-axis, and margin interactions

### Case 23: `wpt-aspect-ratio-cross-size-002`

- [ ] Capture Chromium rectangles for the nested aspect-ratio and cross-size
  feedback branches in the WPT source.
- [ ] Port the smallest static input that exposes the feedback loop and assert
  both the transferred width and final height in Go.
- [ ] Record whether the case is complete, blocked, or unsupported if the
  engine resolves aspect ratio after flex item flow.

### Case 24: `wpt-writing-mode-006`

- [ ] Reduce the writing-mode matrix to named static cases for row, column,

- [ ] Compare logical order and physical rectangles for each named branch;

### Case 28: `wpt-flex-minimum-width-aspect`

- [ ] Port the automatic minimum width and transferred aspect-ratio branches

- [ ] Assert the minimum main-axis width independently from the rendered image

- [ ] Add a regression for the explicit minimum-width override if the source
  case exercises it.

### Case 30: `wpt-auto-margins-column`

- [ ] Preserve both the column auto-margin and `align-self: center` branches

  margin edges relative to the container.
- [ ] Run the test with the existing column cross-axis auto-margin regression.

## Definition of done

Every case has a reviewed static fixture, a source-backed expected behavior,
one named assertion at the chosen seam, and a recorded validation result. Case
29 also has the required PDF page and semantic evidence. A case remains open
when a browser reference or engine capability is missing.

## Out of scope

- Porting cases 31 through 40.
- Building Chromium or copying Blink's C++ harness into Go.
- Treating PDF readability as proof of flex geometry.
