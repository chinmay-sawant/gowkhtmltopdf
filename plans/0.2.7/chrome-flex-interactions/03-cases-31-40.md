## Overview

Convert the final ten manifest cases from scaffolds into reviewed tests. This
batch closes the inventory with reverse multiline flow, fractional flex
factors, minimum-size behavior, intrinsic sizing, border-box cross sizes,
replaced elements, gap decoration, vertical-writing overflow, and min-content.

Several cases describe areas where the engine may intentionally support only a
small print-oriented subset. Preserve that boundary in the result. A case may
finish as `completed`, `blocked`, or `unsupported`, but each result needs a
strict input, an explicit expected behavior, and a reason supported by a test
or reference comparison.

## Executive summary

Use this dependency order:

1. Convert fractional factors and reverse multiline flow.
2. Convert border-box and replaced-element sizing.
3. Convert automatic minimum and intrinsic-content contributions.
4. Convert gap decorations and vertical-writing overflow.
5. Run the complete 40-case inventory and close the interaction-coverage gate.

The final two cases are intrinsic sizing cases. Keep their content measurable
and avoid text-only assertions that can pass when the container contribution is
wrong. Case 39 is a reference case because negative physical coordinates and
overflow behavior are difficult to reduce to a single PDF assertion.

## Existing evidence audit

The current tests show useful partial coverage, but every manifest entry in
this range remains `scaffold` and several fixtures do not match their source.

| Cases | Current evidence | What remains before closure |
| --- | --- | --- |
| 31 | Column-reverse multiline test skips because column wrapping is absent. | Port the source line model and fix or explicitly defer column wrapping. |
| 32 | Row fractional grow passes; row shrink and column branches skip. | Prove factors below one on both axes without rounding away unused space. |
| 33 | A local text-input adaptation passes. | Port the source's input types and automatic minimum-size branches. |
| 34 | Padding and border contributions pass; item-margin contribution skips. | Include outer margins in max-content measurement and match the source matrix. |
| 35 | Local border-box geometry passes. | Replace the generic fixture with the source's stretch and replaced-image setup. |
| 36 | Max-width base-size case skips during shrink-mode regrowth. | Prove the base size before clamp and redistribution after freezing. |
| 37 | Direct replaced aspect-ratio geometry passes. | Replace the scaffold with an SVG fixture and assert the intrinsic 29 by 22 size. |
| 38 | Direct wrapped-gap geometry passes. | Port six fixed items and prove main and cross gaps at known intersections. |
| 39 | The vertical-rl overflow case still skips. | Re-probe it because its skip reason predates the new logical-axis path, then add overflow evidence. |
| 40 | Min-content test skips because the keyword is not implemented. | Use `width: min-content`, measure the constrained contribution, and record the support boundary. |

The existing passing adaptations are starting points only. A case cannot move
to `completed` until the fixture, test, and source-backed behavior agree.

## Phase 3.1: Port reverse flow and fractional factors

### Case 31: `wpt-column-reverse-multiline`

- [ ] Preserve the wrapped column-reverse input from the WPT source and make
  each line's item membership visible in the fixture.
- [ ] Assert line order, item order, main-start packing, and final line height
  relative to the container.
- [ ] Run the case with the existing wrapping and reverse-flow regressions.

### Case 32: `wpt-flex-factor-less-than-one`

- [ ] Port both fractional grow and fractional shrink branches from the WPT
  source into named static subcases.
- [ ] Assert the unused free space or scaled shrink result explicitly; do not
  round fractional results into integer expectations.
- [ ] Run the case with the existing fractional row sizing tests and add the
  column-axis branch if it reaches a different helper.

## Phase 3.2: Port replaced and box-sizing interactions

### Case 33: `wpt-flex-item-compressible`

- [ ] Capture Chromium rectangles for the replaced input's specified-size and
  shrink branches.
- [ ] Assert the specified-size suggestion, final flex item size, and replaced
  content size independently.
- [ ] Record any replaced-element limitation as a strict blocked or unsupported
  result instead of accepting a visually plausible output.

### Case 35: `wpt-flex-cross-size-border-box`

- [ ] Port the border-box and content-box variants from the WPT source.
- [ ] Assert the content cross size and the border-box frame separately for the
  stretched item.
- [ ] Run the case with existing border-box and stretch-with-margin tests.

### Case 36: `wpt-flex-base-size-max-width`

- [ ] Preserve the content-based flex-basis and max-width clamp branches from
  the WPT source.
- [ ] Assert the base size before the clamp, the frozen item size, and the
  redistributed size of the remaining item.
- [ ] Run the case with the existing max-width-freeze regression.

### Case 37: `blink-replaced-aspect-ratio-precision`

- [ ] Translate the Blink C++ setup from

- [ ] Assert the intrinsic 29 by 22 ratio and the 50px column-item constraint

- [ ] Add a PDF or image inspection only if box geometry cannot expose the
  precision loss.

## Phase 3.3: Port intrinsic sizing and gap behavior

### Case 34: `wpt-flex-container-max-content`

- [ ] Capture Chromium's max-content contribution for the outer flex container
  and each item contribution.
- [ ] Port margins, padding, and borders as separate terms so a missing outer
  contribution can be identified.
- [ ] Assert intrinsic width before painting and record unsupported keyword
  behavior separately from a numeric sizing failure.

### Case 38: `blink-gap-decorations-basic`

- [ ] Translate the Blink gap setup into six fixed items and two explicit rows.
- [ ] Assert both main-axis and cross-axis gaps at known intersections, plus

- [ ] Run the case with the existing gap and wrapping tests.

### Case 40: `wpt-flex-container-min-content`

- [ ] Capture the largest constrained item contribution from the WPT source and
  reduce the content to a deterministic static fixture.
- [ ] Assert the min-content contribution independently from max-content and
  from the final painted width.
- [ ] If the engine does not support the required intrinsic keyword, record the
  unsupported result and preserve the strict expected contribution.

## Definition of done

The ledger is complete when cases 31 through 40 each have a reviewed fixture,
an evidence seam, a validation result, and an honest manifest status. The
parent 40-case interaction gate must also report the remaining uncovered
families. Full Chrome parity is not a completion criterion.

## Out of scope

- Rewriting the Chromium test harness in Go.
- Claiming intrinsic keyword support from a readable PDF alone.
- Closing a reference case without a reproducible browser comparison.
