What is GOOD in the Codebase
  • Zero CGO Dependencies: 100% pure Go implementation compiling to static binaries for Linux, macOS, and Windows with CGO_ENABLED=0.
  • Lightning-Fast Execution: 10.5x execution speedup over C++ Qt binary with a microscopic 18 MB peak RSS footprint.
  • 100% Clean Linting & Race Checks: make lint and go test -race exit code 0 under enable-all: true.
  • Canonical Error Sentinels: internal/errs provides domain sentinel errors (ErrNilContext, ErrNilLoader, etc.).
  • Thread-Safe PDF Assembly: pdf.Registry and pdf.Document guarded by sync.RWMutex.
What is BAD (Technical Debt)
  • Struct Context Storage (containedctx): Storing ctx context.Context as struct fields with //nolint:containedctx suppressions.
  • Untagged Union Request (convert.Request): Monolithic struct mixing PDF and Image settings instead of sealed options.
  • Pool Slice Header Escapes: bufPtr = &bufBytes in supersamplePixPool forces slice headers onto the heap.
  • Deep Node Cloning for Page Islands: cloneHTMLNode deep-copies thousands of nodes for header/footer islands.
  • C++ String Reflection in Settings: Reflection-based setters (reflect.ValueOf) used for struct options instead of typed setters.

Code Pattern Comparison: Pool Allocation Fix

Flawed Pattern (Current Heap Escape) 
var bufBytes []byte
bufPtr = &bufBytes
defer supersamplePixPool.Put(bufPtr) // Escapes to heap!
10/10 Idiomatic Go Solution 
type pixBuffer struct { b []byte }
var supersamplePixPool = sync.Pool{
    New: func() any { return &pixBuffer{b: make([]byte, 0, 16<<20)} },
}
Pragmatic Architect's Assessment: Not all discovery findings require immediate rewrite. We evaluate whether proposed refactorings are critical production wins vs over-engineered theoretical nitpicks.
Discovered Finding Classification Lead Architect's Final Verdict
containedctx Struct Storage Pragmatic Internal Choice runContext is short-lived and created solely inside convert.Run. It does not cause long-lived memory leaks, though explicit parameter passing is cleaner Go style.
supersamplePixPool Heap Escape Real Production Fix Heap escaping 16 MiB slice headers undermines the performance benefit of sync.Pool. Replace with pixBuffer struct wrapper immediately.
String Reflection in Settings Necessary CLI Seam CLI flags require parsing string arguments --margin-top 10mm. Keep reflection for CLI flags, but provide typed option builders for library callers.
Coarse Mutex Locking Theoretical Nitpick Rendering is CPU and layout bound, not mutex bound. Coarse sync.RWMutex locks are sufficient until concurrent throughput exceeds 1,000 QPS.

Actionable 5-Phase Roadmap to a True 10/10 Score

Phase 1: Pool Allocation Hardening (Immediate)

Wrap pooled byte slices in dedicated pixBuffer struct wrappers to eliminate slice header heap escaping during supersampling rasterization.

Phase 2: Sealed Options Request API

Decompose monolithic convert.Request into type-safe distinct request structs: PDFRequest and ImageRequest.

Phase 3: Virtual Layout Views for Page Islands

Replace recursive HTML node tree cloning (cloneHTMLNode) with lightweight read-only virtual node views.

Phase 4: Explicit Context Propagation

Thread ctx context.Context explicitly as the 1st parameter to internal helper functions, removing all containedctx nolint suppressions.
