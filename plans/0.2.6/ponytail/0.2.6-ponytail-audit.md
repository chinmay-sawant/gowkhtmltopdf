## Overview

Four read-only reviewers scanned separate packages: public boundaries, CSS and conversion, layout, and PDF/image output. They checked current callers before proposing a deletion. The prior completed Ponytail report at `plans/0.2.6/review/ponytail-go-audit-2026-08-30.md` was a false-positive filter. No completed `PT-GO-*` row is reopened here.

The 40 rows below are the canonical implementation ledger. Implementation landed on the current tree; every row carries the proof result and benchmark record that closed it. The style-memo row was reopened after the full-pipeline hot-path matrix showed the removal was a 1.89x CPU regression, then re-closed with the memo restored. Final restored-tree gates: `make golden` 65/65 fixtures exit 0, `make test` exit 0 across all packages, `make claim-scan` clean, `make lint` exit 0 (golangci-lint + frontend ESLint).

## Executive summary

The highest-value cuts are inactive layout experiments: the unused parallel layout API, section-chrome cloning code, and metadata handoff used only by tests. The next group removes CSS properties that are stored, inherited, and interned but never read by layout or paint. The lower-risk work deletes uncalled wrappers, test-only facades, and hand-written standard-library clones.

Six output-path ideas were not made active because they intentionally trade CPU time, cached memory, or encoded bytes. They are recorded in `04-output.md` as qualified leads, not implementation work.

Measured outcomes, recorded under PT26-GATE-03. The sibling-index cache removal stands: `:nth-child`/`:nth-last-of-type` matching is ~10x slower in the wide-table microbenchmark (0.07 us to 0.73 us per match; sub-microsecond absolute, and the product hot path does not exercise it). The style-resolution memo removal did not stand: the full-pipeline hot-path matrix showed 1.15x-1.89x slower conversion from 2 to 500 pages (500p 591 ms to 1118 ms), so PT26-LAY-09 was reopened and the memo restored. On the restored tree the same matrix is 0.74x-0.91x of the pre-cleanup baseline (500p 485 ms, -18 percent) with 3-4 percent lower `B/op`, and `BenchmarkDeepChromeAndForcedBreaks` is about 28 percent faster than before the cleanup. The benchmark that GATE-03 originally used for LAY-09, `BenchmarkStyleResolutionContext`, did not contain the repeated-structure pattern and under-reported the product impact by an order of magnitude; the full-pipeline matrix is now the recorded proof.
