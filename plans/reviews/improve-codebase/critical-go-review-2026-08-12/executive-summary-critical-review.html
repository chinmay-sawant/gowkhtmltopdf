Why the score is harsh

A document converter's first contract is correct output. XML prepended to PDF bytes and automatic routing to a non-equivalent renderer outweigh clean lint and race output.

Validation floor

go test ./..., go test -race -count=1 ./..., and make lint passed. Fresh 500-page evidence: code benchmark 1.359s / 171.5MB / 966.5K allocs; binary 960ms / 54,632 KiB peak RSS / 1,385,450 bytes, with page count verified.

Keep these choices

  • CLI-independent conversion request and shared render lifecycle.
  • Public ownership snapshots of maps, slices, input, and output.
  • Default-deny local access with loader-owned ACL/time/size policy.
  • Enable-all lint, golden corpus, race testing, and useful conversion benchmarks.
  • Per-layout image reuse, font subset union, and normal deferred-chrome merge.

Repair before calling it robust

  • stdout multiplexes outline XML and PDF.
  • HTML marker/title can select a broken virtual-DOM page-island path.
  • Terminal CLI action requires normal input anyway.
  • Typed image settings lose accepted aliases; typed PDF validates too late.
  • Cancellation/determinism/Document ownership contracts are incomplete.

Representative contract mismatch

--dump-outline && output == "-" → outline = stdout; PDF = stdout; XML is emitted first.
Reject the incompatible CLI pair, or require independently chosen document and outline sinks.

Risks held out of defect scoring: cross-object resource cache/budgets, deep chrome/pagination scaling, fixture-specific render predicates, and cold glyph scanline allocations. Each needs corpus benchmarks before a redesign.

Devil's-advocate conclusion

Necessary now

Reject incompatible stdout sinks. Disable or strictly isolate automatic page islands. Restore terminal command/API behavior. These are concrete correctness problems.

Do not overreact

Do not introduce global caches, a global resource budget, or a full concurrent PDF writer from static suspicion. Measure 1/10/500-page corpora, RSS, fetch bytes, PDF bytes, and visual parity first.

The optimization idea behind page islands is defensible only for an explicitly owned immutable workload with a generic-renderer parity oracle. It is not defensible as hidden behavior selected by document prose, title, and CSS class shape.

Roadmap

  1. P0 Output integrity: isolate stdout formats; remove automatic island selection; add CLI byte-stream and renderer parity tests.
  2. P1 Contract restoration: model TOC-XSL as terminal; repair image settings normalization; preflight typed PDF requests with root errors.
  3. P2 Lifecycle semantics: bounded cancellation in cascade; single-owner or fully synchronized Document decision; deterministic fallback ordering.
  4. P3 Measure scale: repeated-resource, deep chrome, forced-break, and cold-glyph benchmark/corpus evidence before optimization.
  5. P4 Closure: target regressions, lint, tests, race, golden/rendered PDFs, release matrix, then re-score.
